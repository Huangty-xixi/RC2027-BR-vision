# RC2027 下位机（板子）职责与接口

- 依据：RC2027 主赛（女娲补天）方案 —— 算法全部搬到车上电脑（NUC），板子只留执行与安全
- 参照：26 赛季 `26代码\RC2026\主赛R2\RC26_H7_R2` 的实际代码
- 配套：`RC2027_ROS2架构清单.md`（电脑侧）

---

## 0. 一句话

**板子只做四件事：转电机、读传感器、执行命令、保命。不做任何决策。**

电脑负责"想"，板子负责"动"和"停"。想错了是电脑的问题；动了停不下来，是板子的问题。

---

## 1. 板子上留什么

| 块 | 具体做什么 | 为什么不能搬到电脑 |
|---|---|---|
| **电机闭环** | 1kHz 电流环 / 速度环，CAN 收发（M3508、DM 电机） | 1kHz 是硬实时，Linux 非实时内核顶不住 |
| **传感器采集** | IMU、轮速/编码器、限位开关、电流、温度；**并在板子上打时间戳** | 数据在它那儿产生；时间戳必须源头打，事后补的是假的 |
| **执行命令** | 把电脑给的"轮子转多快、升降到多高、夹爪开多大"变成实际输出 | 它就是手 |
| **保命** | 心跳超时缓停、急停、限位保护、过温保护 | 电脑死机时，只有它还能停 |

### 1.1 急停必须硬线直连

急停按钮/开关**直接进板子的 IO**，不走电脑。因为最需要急停的时候，往往就是电脑出问题的时候——信号绕一圈电脑再回来，等于没有。

## 3. 执行命令详解

### 3.1 电脑发下来的是什么

| 发什么 | 格式 | 为什么这么给 |
|---|---|---|
| 底盘 | **4 个轮子的目标转速**（如 0~4000 rpm） | 不给 PWM、不给电流；板子自己做速度环。轮距/轮径的解算放在电脑，**换底盘不用刷板子固件** |
| 升降 | 目标高度（mm）或目标计数 | 板子走位置环，负责到位 |
| 夹爪 | 目标开合（mm）或 PWM 脉宽 | 位置模式、力模式都留 |
| 翻转 / 武器 | 动作序号或目标角度 | 一次触发一次动作，动作本身由板子执行完 |
| 使能 / 模式 | 每个机构：使能 / 阻尼 / 关闭 | 阻尼模式用于重试时人工归位 |
| 心跳 | 序号 + 时间戳 | 超时兜底靠它 |

### 3.2 板子拿到后走五步

1. **解析** —— 拆帧、验长度、验校验和。
2. **判新旧** —— 序号比已记录的小就丢弃，防旧包晚到覆盖新目标（串口/网络都可能乱序）。
3. **夹紧** —— 见 3.3。
4. **写目标** —— 写进"最后有效目标值"变量（这是超时兜底的基础）。
5. **闭环输出** —— 1kHz 任务读目标值，跑 PID，发 CAN 电流或 PWM。

**例子**：

> 电脑发来：轮速 `[3000,3000,3000,3000]` + 升降 `250mm` + 夹爪 `闭合 30%`（序号 1205）
> 板子：校验通过 → 1205 > 上次 1204 → 3000 未超上限、变化斜率也在允许范围
> → 写入目标 → 1kHz 任务跑速度环发 CAN 电流 → 升降位置环走到 250mm → 夹爪输出 PWM 到 30%

### 3.3 "夹紧"夹什么

决策搬到电脑后，"电脑算错"是**新增的风险**，由板子这道夹紧挡住：

| 对象 | 夹什么 |
|---|---|
| 轮速 | 限绝对值上限；**限变化率**（每 10ms 最多变多少），防打滑、防电流冲击 |
| 升降 | 限行程上下限（机械限位前留余量）；限速度；上电先慢速找零位 |
| 夹爪 | **限电流/力矩上限**——方块是瓦楞纸盒（塔基/中段 200~350g），夹力大了直接压扁，塔就废了 |
| 通用 | 任何值超范围 → 夹到边界，并记一条故障上报电脑 |

### 3.4 心跳断了怎么"缓停"

**不能一刀切断电**，要分类处理：

| 机构 | 超时后怎么做 | 为什么不能断电 |
|---|---|---|
| 轮子 | 按最大减速度降到 0（如 200ms 内） | 直接断会甩尾、翻车 |
| 升降 | **保持当前位置**（或缓慢降到安全位） | 断电会直接掉下来 |
| 夹爪 | **保持夹紧** | 一松方块就掉，还可能砸到东西 |
| 武器 / 翻转 | 停止动作，停在当前状态 | 别在场地中间乱动 |

## 4. 帧格式与命令字

沿用 26 赛季帧：`0xA5 0x5A`，**新增 2 字节序号**用于判新旧。

```
帧 = 头(2) | 命令字(1) | 长度(1) | 序号(2) | 载荷(n) | 校验(1)
```

### 4.1 下行（电脑 → 板子）

| 命令字 | 名称 | 载荷 | 频率 |
|---|---|---|---|
| `0x30` | `MOTOR_TARGET` | 4 轮目标转速 + 时间戳 | 100 Hz |
| `0x31` | `MECH_TARGET` | 升降高度 / 夹爪开合 / 翻转动作 | 50 Hz |
| `0x32` | `MODE_SET` | 机构使能 / 阻尼 / 关闭、控制模式 | 事件 |
| `0x33` | `HEARTBEAT` | 序号 | 10 Hz |

### 4.2 上行（板子 → 电脑）

| 命令字 | 名称 | 载荷 | 频率 |
|---|---|---|---|
| `0x40` | `MOTOR_STATE` | 转速 / 电流 / 温度 | 100 Hz |
| `0x41` | `IMU_RAW` | 角速度 / 加速度 / 姿态 + 时间戳 | 200 Hz |
| `0x42` | `JOINT_STATE` | 升降/夹爪关节角 | 100 Hz |
| `0x43` | `FAULT_ESTOP` | 故障码 / 急停状态 / 夹紧告警 | 事件 |
| `0x44` | `ACK` | 被确认的命令字 + 结果码 | 事件 |

### 4.3 链路带宽（要提前定，别到最后才发现不够）

粗算上行：IMU 200Hz（约 40 字节/帧）≈ 8 KB/s，加上轮速与关节 100Hz ≈ 3~5 KB/s，合计 **10~13 KB/s**，已经顶到串口 115200（约 11.5 KB/s）的天花板。

**结论：走 USB CDC，或波特率 ≥ 460800。** 26 赛季那种 115200 只够跑 50Hz 里程计，搬了算法之后不够。

## 5. 板子侧代码结构（5 个文件）

| 文件 | 干什么 | 26 赛季对应 |
|---|---|---|
| `cmd_parser.c` | 拆帧、校验、判新旧 | `upper_pc_protocol.c` |
| `motion_target.c` | 目标值 + 夹紧 + 缓停状态，**唯一的目标值出口** | 新写（26 赛季散在各处） |
| `Can_Task.c` | 1kHz：读目标 → PID → CAN 输出 | 沿用 |
| `Sensor_Task.c` | 采样 + 打戳 + 打包上报 | 沿用 |
| `safety.c` | 心跳、限位、过温、急停 | 新写（26 赛季散在各处） |

**约定：谁都不许绕过 `motion_target.c` 直接写电机。** 这样夹紧和缓停只有一处实现，不会漏。

---

## 6. 三个容易踩的坑

1. **单位写死在协议里**：rpm 还是 rad/s、mm 还是编码器计数。两边各理解一套，最费调试时间。
2. **控制模式跟着命令走**：速度 / 位置 / 阻尼，别让板子自己猜。
3. **时间戳在板子上打**：电脑要融合 IMU（200Hz）和轮速（100Hz），两个数据必须对齐到同一时刻。

| 项 | 谁定 | 备注 |
